# ❗ 重要 - 首次启动（V10.3+） ❗

刷入固件后首次启动时，**所有通道必须为空**。

从 **V10.3** 开始，固件会在首次启动时校准空通道检测。

如果你在插入耗材的情况下刷入了固件：
- 取出所有耗材
- 按住任意一个缓冲位约 **5 秒** 重新校准

# ❗ 二代打印机注意事项
很多人会犯错，因为图纸具有误导性，从示意图中并不总是清楚显示的是插头还是插座。因此，Signal A 和 Signal B 经常被接反。

如果你的 BMCU 未被二代打印机识别，请尝试交换 Signal A 和 Signal B——但请确保你完全清楚自己在做什么。


# HMS 警告状态

此固件版本在**打印机启动后会立即触发 HMS 警告**。

重要说明：
- 此 HMS 警告**不会阻止 BMCU 工作**
- **不需要重启打印机**
- **不影响打印**
- 尽管有警告，打印机正常工作
- 此问题**纯粹是视觉/信息性的**（仅显示 HMS 图标）

目前，此 HMS 警告是此固件版本的已知且可接受的行为。

如果 Bambu Studio 中的 HMS 警告让你困扰：
我制作了一个修改版 Bambu Studio，可以绕过这个特定的 AMS 兼容性警告，这样你就看不到了。
其他 HMS 警告仍然会显示（如果发生），因此 HMS 仍然有用。

## 下载

请从 **"Releases"** 部分（GitHub 页面右侧）下载即用固件。
所有固件变体都在那里生成，并附带 **.txt 说明文档**，指导你选择哪个版本。

本仓库的发布包 `firmwares_v11.0.zip` 解压后按 **5 步**依次选择：

1. **有 OLED 屏吗？** 有 → 顶层；没有 → 进 `noled/`
2. **打印机型号 / 送料力度？** → `standard(A1)` / `high_force_load(P1S)` / `soft_load(A1)`
3. **板子是 DM 双微动（带自动加载）吗？** 是 → `AUTOLOAD`；否 → `NO_AUTOLOAD`
4. **在线灯要不要显示耗材颜色？** → `FILAMENT_RGB_ON` / `FILAMENT_RGB_OFF`
5. **AMS 地址**：新装机用 `AMS_AUTO`；老配置按原来的 `AMS_A` / `AMS_B` / `AMS_C` / `AMS_D`；单通道用 `SOLO`

每一层目录下都有一份 `README.md`，说明当前这一步该选什么。

发布包内共 **144 个固件**（3 模式 × 2 屏幕 × 2 加载方式 × 2 耗材色 × 6 槽位 = 144），
并附带 `manifest.txt`（含每个固件的 SHA256 / CRC32 / 字节数），可用于核对下载完整性。

文件名与回抽长度：

| 位置 | 文件名 | 回抽长度 |
|---|---|---|
| `NO_AUTOLOAD/…/AMS_<槽>/` | `ams_<槽>_0.20f.bin` | 固定 0.20 米 |
| `NO_AUTOLOAD/…/SOLO/` | `solo_0.095f.bin` | 固定 0.095 米 |
| `AUTOLOAD/…/AMS_<槽>/` | `ams_<槽>_2.00f_auto.bin` | 由自动加载状态机接管 |
| `AUTOLOAD/…/SOLO/` | `solo_2.00f_auto.bin` | 由自动加载状态机接管 |

固件向打印机上报的版本号为 `11.00.00.00`。

## 刷机

在以下系统上刷入 BMCU（USB 或 TTL）：
- Windows
- Linux
- macOS
- Android

请使用 **BMCU Flasher**：
https://github.com/jarczakpawel/BMCU-Flasher

预编译的可执行文件在 **Releases** 部分提供。

刷机过程非常简单，**不需要 wchisptool**。

你可以通过两种方式刷入固件：
- **在线刷机**：直接使用内置向导（推荐）
  → 刷机工具会自动下载正确的固件，**无需手动下载 .bin 文件**。
- **本地刷机**：使用你自行下载的固件文件。

刷机工具还支持 **Android**，你甚至可以直接用**手机**刷入 BMCU 🙂

重要提示：
- 刷入 BMCU 时**不要**连接打印机。
- 打印机开机时**不要**连接或断开 BMCU（有损坏 BMCU 和/或打印机主板的风险）。

## 耗材回退长度说明

回退长度必须从打印机内部 AMS 分流器末端开始计算
（即 AMS 塑料件中四根 PTFE 管进入的那个位置）。

示例：
- BMCU 到 AMS 分流器末端的距离：约 9.0 厘米
- SOLO 固件回退约 9.5 厘米，超出分流器约 0.5 厘米

计算你自己的回退长度时：
- 始终从 AMS 分流器末端开始测量
- 加上所需距离，再加上约 9 厘米（取决于你的配置）

## AMS_AUTO / AMS_A / AMS_B / AMS_C / AMS_D 固件

### AMS_AUTO —— 推荐

**AMS_AUTO 是新装机的推荐选项。**

它的工作方式与 Bambu 原厂 AMS 寻址系统一致 —— 接入的 BMCU 单元会被
**自动枚举并分配各自的 AMS 编号**。

大多数情况下，你应该使用 **AMS_AUTO**。

### AMS_A / AMS_B / AMS_C / AMS_D —— 旧版

这些是旧的手工指定槽位固件。

现在它们被视为**旧版（legacy）**，不再是推荐配置。

仅在 **AMS_AUTO 在你的环境下工作不正常**时使用。

## 校准 / 重新校准

正确的校准非常重要，因为校准之后 BMCU 才知道**每个通道缓冲机构的精确行程极限**。

开始校准前，请先从所有通道取出耗材。

进入校准模式：

1. 按住任意一个缓冲机构约 **5 秒**。
2. 一开始**不要移动任何东西**。BMCU 会记录每个缓冲机构当前的中位/中心位置。
3. 当该通道 LED 开始**闪烁蓝色**时，把该通道的缓冲机构**完全推到底**，保持约 **1 秒**，然后松开。
4. 当该通道 LED 开始**闪烁红色**时，把缓冲机构**完全拉到头**，保持约 **1 秒**，然后松开。
5. 对每个通道重复同样的操作。

校准完成后，BMCU 就会知道**每个通道缓冲机构的最小、中心与最大位置**。

如果需要，你可以随时按上述步骤重新校准（先取出全部耗材，再按住任意一个缓冲机构约 5 秒进入校准模式）。

## 安全与使用须知

- 刷入 BMCU 时不要连接打印机
- 打印机开机时不要断开 BMCU
- BMCU 连接时不要更新打印机固件
- 只在打印机完全关机（拔掉电源）时连接/断开 BMCU。带电操作可能损坏 BMCU 和/或打印机主板。

这些建议基于社区反馈。
并非所有故障场景都经过测试。

在 BMCU 连接状态下将打印机模式从 AMS Lite 切换为 AMS 在测试中未出现问题，但不建议这样做。

## 提交 Bug 报告前

请先确认以下基本事项：
- 确保你刷入了正确的固件变体，并正确按照刷机教程操作。
- 确保你确实拥有 **BMCU 370C 带霍尔传感器版本**。
    - 唯一可靠的验证方式是打开模块检查 PCB。
    - 部分卖家会混装模块，尝试清理旧的 **370x** 板——有时一套中的 1-2 个模块可能是 370x。
- 如果你遇到打印机端问题：
    - 确认你的打印机固件已是最新版本
    - 执行出厂重置（这通常能修复奇怪的 AMS 相关问题）
- 如果耗材检测行为异常：
    - 先不连接 BMCU 启动一次打印机
    - 然后连接 BMCU 再次测试
- 在创建帖子前先做几次实际测试。
  打印机可能存在不相关的问题（罕见但确实发生）——有些用户甚至无法自动更新打印机固件，必须通过 SD 卡更新。

### 用户可见变更
- **合并上游 V11 全部功能**：代码、协议、参数与上游 `jarczakpawel/BMCU-C-PJARCZAK` 最新主线完全同步（`git log main..upstream/main` 为空）。

- **修复 AMS_AUTO 固件 OLED 恒显示 EMPTY**：AMS_AUTO 寻址下 `ams[4]` 越界落到一片恒为 0 的内存，导致耗材装满后 OLED 仍显示 EMPTY，且上报给打印机的状态同样错误。本版修复后耗材信息可正确显示与上报。
- **修复「耗材色指示灯不亮」**：FILAMENT_RGB_ON 固件自 V10.5.6 起因两层亮度叠加（上游 12.5% × 本 fork 10%）净亮度只剩 1.28%，纯红 255 最终只剩 4/255，肉眼等同熄灭。本版移除多余的一层，耗材色亮度回到 **10%**，与槽位状态灯一致，且不再把色谱压缩到 5 档。
- **固件数量大幅精简**：由 2424 个收敛为 **144 个**（3 模式 × 2 OLED × 2 DM × 2 RGB × 6 槽位）。NO_AUTOLOAD 分支原先独占 39 档回抽长度（0.10~2.00 m），占整个矩阵约 97%，实际几乎无人挑选，现统一为默认 **0.20 m**；AUTOLOAD 与 SOLO 不受影响，仍提供 0.095 / 0.20 / 2.00 等档位。
- **升级后必须重新校准**：全量定点化后校准数据的存储格式已变更，旧固件的校准会被判为无效并强制重校。请按上方「校准 / 重新校准」章节重新校准全部通道。
- **Flash 占用显著下降**：全量定点化消除了软件浮点，最大固件由 61088 B 降至 **58728 / 61440 B**（余量 2712 B），OLED 变体重新装得下（改动前超容量约 4.8 KB）。
- **上报版本号**：`11.00.00.00`（沿用上游 V11 的版本号）。

## V6

## 框架
- 移除 Arduino Core（PlatformIO: framework = arduino）——整个固件重写为纯 CH32（WCH SDK / noneos）。
- 直接使用硬件定时器、DMA 和中断——无 Arduino 延时，无随机时序，确定性实时行为。
- 更快且正确的 Flash 操作（WCH Fast API）——稳定的写入，更快，不会损坏相邻数据。

## ADC_DMA
- 将 DMA 写入与 CPU 读取分离——之前读取和 DMA 覆盖缓冲区同时发生。
- 滤波在后台计算（DMA 半/全完成），不在读取时——之前 `get_value()` 阻塞 CPU 并破坏时序。
- 恒定 CPU 负载——之前更大的滤波窗口会拖慢系统。
- DMA 错误处理

## 总线（BambuBus + AHUB）
- 修复 RX/TX 缓冲区竞态（同时读取和覆盖同一缓冲区）。
- 使用快照解析代替直接操作缓冲区
- 确定性的帧处理时序——恒定 CPU 开销，与数据包长度无关。
- 传输错误鲁棒性——一个坏数据包不会破坏整个系统状态。

## Flash / NVM
- Flash 按页（256B）写入，而非擦除/编程整个扇区（4KB）
- 仅在数据实际更改时写入
- 硬件 CRC 校验 Flash + 读取验证
- AMS 数据拆分为独立记录——更改一个耗材不会重写整个结构。

## 软件 I2C / AS5600
- 从 Arduino 重写，移除时序 Bug 和 Arduino "魔法"。
- 正确的 ACK/NACK、START/STOP、恢复处理
- 出错通道的硬隔离

## 运动 / 机械
- 更平滑的电机控制
- 新增校准缓冲——耗材保持在中立位置，无不必要的张力。
- 更好的状态转换——无突变和急刹车。

## 杂项
- CRC8 / CRC16 重写为简单 C + 查找表——更快、确定性、无对象和无运行时初始化。
- 部分解构 include 关系
- 以及更多——固件为后续开发做好了准备

许多解决方案是刻意过度工程化的。
所有实现主要是为了个人使用和实验。

固件在开发过程中被广泛使用，
在实际使用中未观察到实际问题。
